# v0.3.0 plan

Status: draft, 2026-11-03. Theme: **scale and interop without giving up the file
core.**

## Settled — do not re-open

- One task entity. Requirements and defects share it; the difference lives in
  acceptance and in whether the plan gates re-open.
- Files are the source of truth; `evidence.jsonl` and `audit.jsonl` are
  append-only, `state.json` is capped, `leases.json` holds only active leases.
- The product is the enforcement layer: gates, evidence, leases, questions,
  stale approvals. Not a scheduler, not a UI, not a model.

## Candidates

### 1. Per-task evidence shards — only if a project passes ~10k records

`evidence/T-001.jsonl` would make `verify` O(task) instead of O(log). Cost: many
files, migration, and `compact` across shards. **Trigger:** a real project where
`verify` takes >100 ms.

### 2. A2A task-state mapping

Map the six Trellis statuses to A2A's task lifecycle and expose a read-only
export (`trellis export --a2a`) so another agent runtime can observe a task
without reading the file format. No A2A server in 0.3.0; an adapter is enough.

**Acceptance:** a documented table, a JSON export with stable field names, a
test that a Trellis task round-trips through the mapping.

### 3. Signed actor tokens (optional identity)

`--by` is self-declared. A token file (`.trellis/actors.json`) mapping
`role:name` to a public key, with `trellis actor sign`, would let a reviewer
verify who approved. This is authentication, and it is a larger change than it
sounds; keep it out unless a real multi-agent deployment needs it.

### 4. Distribution fallback

npm registration is blocked. Options: attach the `npm pack` tarball to every
GitHub Release (install by URL), or publish to JSR (GitHub auth). Pick one and
document it; do not maintain both.

### 5. Retention beyond retracted evidence

`compact --archive-retracted` covers the safe case. Archiving pass/fail evidence
of completed tasks needs a **summary record** so `verify` and G6 still hold;
that is a design decision, not a flag.

## Suggested 0.3.0 scope

Take **2 (A2A mapping)** and **4 (distribution)**, plus the documentation debt:

- [x] `trellis export --a2a` with a documented state mapping
- [x] release tarball script and install-by-URL documentation (attach per release)
- [ ] Chinese translations kept in sync (`SPEC.zh.md`, `CONTRIBUTING.zh.md`)
- [ ] `v0.3.0` tag and release notes

## Non-goals

- SQLite or an HTTP server before evidence passes 100k records
- multi-host coordination
- a web UI
- a separate defect entity

## Definition of done

- `npm test` passes on Node 20/22/24 and Windows
- every new blocking rule has a negative control
- SPEC, README (both languages) and CHANGELOG describe the released behaviour
